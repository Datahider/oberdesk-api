# API v1

`v1` импортирован из фактического production-состояния `api.oberdesk.ru`.

## Размещение

- Production: `/home/oberdesk-api/htdocs/api.oberdesk.ru/v1`.
- Публичный URL: `https://api.oberdesk.ru/v1`.
- Конфигурация: `v1/etc/config.php`, вне Git.
- Зависимости: `v1/vendor`, вне Git.

## Существующие маршруты

- `GET /v1/me`;
- `GET /v1/groups`;
- `GET /v1/group/{group_id}`;
- `GET /v1/group/{group_id}/threads`;
- `GET /v1/thread/{thread_id}`;
- `GET /v1/thread/{thread_id}/messages`.
- `GET /v1/pacer/time-entries?subject={id}&project_groups[]={group}&from={ISO-8601}&to={ISO-8601}`.
- `POST /v1/tickets`.

На момент импорта `/me` и `/groups` используют серверную конфигурацию и БД. Остальные маршруты частично возвращают тестовые данные из `StubData`.

## Pacer time entries

Метод возвращает интервалы учёта времени для пейсера:

- `subject` — обязательный положительный Telegram ID авторизованного пользователя;
- таймер определяется сервером по точному совпадению `timers.subject`; отсутствие таймера или несколько таймеров для одного пользователя считается ошибкой данных;
- `project_groups[]` — обязательный непустой массив точных значений `chat_groups.chat_group`, без дублей;
- включаются только события выбранного таймера, у которых `timer_events.project` входит хотя бы в одну выбранную группу проектов;
- `from` включается, `to` не включается;
- незавершённое событие заканчивается текущим моментом;
- ответ содержит `id`, `task_id`, `task_type`, `started_at`, `ended_at`, `duration_seconds` и `is_running`;
- значения MySQL `DATETIME` интерпретируются как `Europe/Moscow` и возвращаются с корректным смещением `+03:00`;
- `task_type` берётся из `topics.type`, отсутствие связанной задачи является ошибкой данных;
- метод только читает БД.

## Создание заявки

`POST /v1/tickets` ставит в очередь Oberbot создание заявки в группе клиента. Контракт данных и обработки на стороне бота — `API_TICKET_CONTRACT.md` в репозитории Oberbot.

Запрос:

- заголовок `Authorization: Bearer <secret>` — секрет из `[apikey]`;
- тело — JSON-объект:
  - `group_id` — целое, не ноль: Telegram ID группы;
  - `title` — непустая строка до 128 символов: заголовок заявки;
  - `text` — непустая строка: первое сообщение заявки.

Обработка:

- ключ ищется по точному совпадению `secret`;
- у ключа должна быть строка `[chat_apikey]` для `group_id` с правом `create_ticket`;
- создаётся `[api_ticket_request]` (`apikey_id`, `chat_id`, `user_id` = `apikey.user_id`, `title`, `text`, `created`) и `DBPendingJob` с `job_class` = `losthost\Oberbot\background\CreateTicketFromApi`, `job_args` = id запроса, `start_in_background` = `true`, `start_time` = текущий момент;
- запись запроса и задания выполняется в одной транзакции.

Ответы:

| HTTP | Тело | Когда |
|---|---|---|
| 200 | `{"ok": true, "request_id": <int>}` | запрос принят в очередь |
| 400 | `{"ok": false, "error": "<текст>"}` | невалидный JSON или поля |
| 401 | `{"ok": false, "error": "unauthorized"}` | нет заголовка или неизвестный секрет |
| 403 | `{"ok": false, "error": "forbidden"}` | у ключа нет `create_ticket` для группы |

Заявка создаётся асинхронно; результат хранится в `api_ticket_request.ticket_id` или `api_ticket_request.error`.
